## Инфраструктура публикации Таро (новое 26.08)
- CF tunnel «taro-guide» id=73546d0e-efe3-4e13-9f23-9aae563dc11f, CNAME taro.jetserg.top создан через API.
- Конфиг ingress залит в ОБЛАКО (API PUT configurations): taro.jetserg.top → http://localhost:8090. Локальный ~/.cloudflared/taro-tunnel.yml существует, но cloudflared работает с --token (EnvironmentFile ~/.cloudflared/taro-token.env, chmod 600) — origin cert.pem на сервере нет, поэтому credentials-файл не используется!
- systemd user: taro-site.service (python3 -m http.server 8090 --bind 127.0.0.1, WorkingDirectory webapp/) + taro-tunnel.service. Оба enabled.
- PITFALL: если менять ingress туннеля, менять надо через Cloudflare API (PUT /accounts/{acct}/cfd_tunnel/{id}/configurations) — не только в локальном yml!
- PITFALL: CF кэширует 404-ответы на max-age=14400 (4ч). Если после настройки туннеля какие-то URL отдают 404 — это может быть закэшированный старый ответ; проверяй с query-string ?x=1. Пурж кэша недоступен текущим токеном (нет Zone Cache Purge права).
- CLOUDFLARE_API_TOKEN лежит в /home/serg/.hermes/.env (права: зоны DNS+cfd_tunnel ок, purge_cache нет). Python urllib работает с ним напрямую.
